# DDTrans 后续优化计划

日期：2026-10-29。当前开发状态以 [虚拟麦克风开发记录](virtual-microphone-development-2026-10-29.md) 为准。

## 已完成的开发

- 共享媒体宿主、主窗与悬浮窗生命周期、成对字幕、说话人归段、尾段保存与 SQLite 增量落库。
- 48 kHz 单声道混音、原声/译音独立增益、TTS 开关、独立监听、明确的输出端点绑定与原子保存设置。
- 自有最小 Windows 11 x64 驱动源码：配对 Render/Capture 端点、48 kHz/mono/PCM16、100 ms 有界桥、溢出丢旧与欠载静音。
- 本地 WDK 恢复、驱动编译、离线音频缓冲测试、INF 检查、目录生成、开发签名及显式安装/移除工具。
- 设置页发言翻译：默认发送语言、自动选择实体麦克风、DDTrans 端点配对、设备缺失提示。发送语言与收听语言分开保存；发言模式的原声增益与收听模式独立。

源码和开发包不代表设备已经可用。当前机器未安装或加载 DDTrans 驱动，尚未完成任何外部应用从 DDTrans Virtual Microphone 收音的实测。当前原声增益控制 DDTrans 的混音，不控制游戏或会议的 Windows 应用音量。

## 下一步顺序

### 1. 安排驱动测试环境并验证真实收音

开发包是本地测试签名，当前主机 Secure Boot 开启、测试签名未启用。到加载验证时再由用户安排测试环境和所需重启；简单重启不会添加设备，不自动更改启动设置。先运行只读检查，再完成安装、端点枚举、原生 WASAPI Render→Capture 探针和至少一个会议/录音客户端验证。

验收：两端点名称与方向正确，997 Hz 测试音可从 Capture 录到，停止后静音；设置页开始发言翻译后外部客户端收到译音，加入原声后比例正确；本地监听开关不改变发送，系统回采不会把远端声音送回对方。

### 2. 完成驱动生命周期和发布

覆盖新装、升级、卸载、设备禁用/启用、睡眠唤醒、多共享客户端、应用异常退出与长会话。记录延迟、丢弃/欠载和内存趋势。按实际发布范围准备 Microsoft 签名与安装体验；开发测试签名包不作为正式发行包。

### 3. 完善运行稳定性与声音控制

覆盖断网、重连、采集权限变化、实体麦克风切换及长时间 TTS 队列；确保暂停/停止后不重复发送旧音频，设备失效时显示可操作提示。若要控制游戏/会议本身的外放音量，再增加明确选择目标应用的 Windows 会话音量控制。

### 4. 整理数据库与配置归属

补充媒体保留、备份、导出、删除与孤儿媒体清理策略；增加会话内说话人别名与筛选；统一热词配置来源和回显。以备份、恢复和删除的可检查结果验收。

### 5. 扩展产品能力

双向翻译先拆清本地发言与远端收听的独立会话、语言、采集与输出，避免回送。多模型管理、本地视频翻译、WebRTC/AOQ 和实时变声按独立需求推进；新连接协议先由模型实际支持和测量结果决定。

当前的验证范围、可重复命令和本地证据路径见 [开发记录](virtual-microphone-development-2026-10-29.md)，系统设备与签名方案见 [制作方案](virtual-microphone-production-plan-2026-10-29.md)。
